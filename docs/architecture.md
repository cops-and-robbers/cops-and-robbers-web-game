# 구조

```
shared/logic.js    규칙, 봇, 지도 생성. 화면을 몰라요. createGameLogic() 으로 방마다 따로 만들어요
shared/view.js     사람마다 보낼 내용을 정해요. 시야 밖 상대는 빼요
server/route.ts    열쇠와 출처를 확인하고 방 코드에 맞는 방으로 연결해요. 입구 두 곳이 함께 써요
server/index.ts    workers.dev 입구이자 방 서버 Worker
server/room.ts     방 하나. 대기실, 판 진행, 끊김 처리, 비용 안전장치
server/directory.ts 열린 방 목록. 공개 방만 자기 상태를 알려요
gateway/           pages.dev 입구와 왕복 시간 측정 페이지. 방 서버는 묶음으로 연결해요
client/game.js     그리기와 조작. 혼자 할 때는 여기서 규칙과 봇을 돌려요
client/net.js      사람끼리 할 때. 규칙을 돌리지 않고 서버가 보낸 것만 그려요
client/guide.js    게임 방법 안내. 실제 엔진에 대본을 넣어 장면 여섯 개를 연기시켜요
client/i18n.js     화면 문구(한국어, 영어, 일본어)와 언어 고르기. 문서 머리에서 먼저 읽혀요
client/brand/      앱과 같은 그림(글자 로고, 캐릭터, 배경, 경찰차, 승리 그림, 아이콘). 빌드할 때 화면 파일에 묶여 들어가요
tools/             검사와 빌드
```

## 한 판의 흐름

1. 브라우저가 게임 파일을 받아요.
2. WebSocket 으로 `/room/<코드>` 에 접속해요. 같은 코드는 같은 방 서버로 모여요.
3. 대기 중에는 방이 잠들어요. 쉬는 동안 실행 시간이 잡히지 않아요.
4. 방장이 시작하면 초당 20번 규칙을 돌리고, 사람마다 `viewFor` 결과를 보내요. 이 동안에는 타이머 때문에 잠들지 않아요.
5. 빈자리와 끊긴 사람의 자리는 봇이 맡아요. 30초 안에 돌아오면 이어 해요.
6. 판이 끝나면 타이머를 끄고 대기실로 돌아가요.

## 왜 이렇게 했나

| 결정 | 이유 |
| --- | --- |
| 서버가 판정 | 숨는 게임이라 기기끼리 위치를 주고받으면 통신만 봐도 숨은 상대가 보여요 |
| 방마다 Durable Object 하나 | 방 상태를 한곳에 두기 쉽고, 서버 대수를 관리하지 않아요 |
| 열린 방 목록은 따로 하나 | 방들은 서로를 몰라요. 공개 방만 목록에 알리게 해서 비밀 방은 목록 서버가 아예 몰라요 |
| 처음에는 비밀 방 | 친구끼리 하는 게임이라 모르는 사람이 갑자기 들어오지 않게 해요. 방장이 대기실에서 공개로 바꿔요 |
| 방마다 `createGameLogic()` | 규칙 파일이 지도를 안에 들고 있어요. 같은 메모리를 쓰는 방끼리 지도가 섞이지 않게 해요 |
| 규칙은 JavaScript 그대로 | 동작하는 코드를 살려요. TypeScript 로는 건드릴 때 조금씩 옮겨요 |
| 접속은 `pages.dev` 입구로 | 한국에서 `workers.dev` 는 미국으로 들어가 왕복이 200ms 를 넘겼고, `pages.dev` 는 서울로 들어가 KT 폰에서 36ms 였어요. 아래 "입구 측정" 참고 |
| 방 위치를 지정하지 않음 | 방은 처음 들어온 곳 근처에 생겨요. `pages.dev` 로 들어오면 지정 없이 서울이고, 입구가 멀 때 지정하면 오히려 느려졌어요 |
| 게임 엔진 없음 | 이동, 부딪힘, 시야가 이미 있어요. 폰에서 느리면 그리는 부분만 PixiJS 를 검토해요 |

## 입구 측정

2026-11-05 새벽, 25번 왕복의 중간값이에요.

| 입구 | KT 폰 | KT 회선 PC |
| --- | --- | --- |
| `pages.dev` | 36ms (입구 서울, 방 서울) | 13ms (서울, 서울) |
| `pages.dev` + 방 위치 지정 | 44ms (서울, 서울) | 14ms (서울, 서울) |
| `workers.dev` | 233ms (LA, 산호세) | 181ms (댈러스, 댈러스) |
| `workers.dev` + 방 위치 지정 | 329ms (댈러스, 오사카) | 290ms (LA, 서울) |

- 측정 페이지로 SKT 와 LG U+, 저녁 시간은 아직 재지 않았어요. 폰 통신 시험 단계에서 다시 재요
- 이 경로는 Cloudflare 가 약속한 것이 아니에요. 바뀌면 입구만 옮길 수 있게 방 연결을 `server/route.ts` 한곳에 뒀어요
- 우리 도메인을 입구에 연결하면 이 경로를 잃을 수 있어요. 무료 요금제 주소는 한국에서 해외로 연결된다는 신고가 많아요. 연결하기 전에 같은 방법으로 재요

## 웹사이트와의 관계

게임은 웹사이트(`dongsim-web`)와 다른 저장소예요. 게임 화면과 서버를 함께 Cloudflare 로 올려 버전이 어긋나지 않게 하고, 사이트에는 버튼과 주소 연결만 둬요. 게임 빌드가 실패해도 사이트 배포는 막히지 않아요.

## 검사

| 명령 | 보는 것 |
| --- | --- |
| `pnpm run check:map` | 지도가 끊기거나 겹치지 않는지 |
| `pnpm run check:rooms` | 방 여러 개가 섞이지 않는지. 일부러 섞어 검사가 잡는 것도 확인해요 |
| `pnpm run check:view` | 숨은 상대의 이름과 위치가 새지 않는지 |
| `pnpm run check:server` | 실제 런타임에서 가짜 접속 4개로 한 판. 입장, 끊김, 재접속, 판 끝 |
| `gateway/public/rtt.html` (주소 `/rtt`) | 폰에서 열어 통신사별 입구와 방 위치, 왕복 시간을 재요. 서버를 올린 뒤에 써요 |
| `pnpm run check:balance` | 봇끼리 돌려 승률과 판 길이. 20판이면 오차가 ±20%쯤이에요 |
