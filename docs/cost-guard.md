# 비용 지키기

**돈이 나가면 안 돼요.** 올리기 전에 이 문서를 확인해요.

## 무료 한도 (Durable Objects, Workers 무료 요금제)

| 항목 | 하루 한도 | 넘으면 |
| --- | --- | --- |
| 요청 | 100,000건 | 오류로 막혀요. 오전 9시(UTC 0시)에 풀려요 |
| 실행량 | 13,000 GB-s | 위와 같아요 |

- 받는 WebSocket 메시지는 20개를 1건으로 쳐요. 보내는 메시지는 무료예요
- 무료 요금제는 한도를 넘어도 청구되지 않고 막혀요. **유료 요금제(Workers Paid)면 넘은 만큼 청구되니, 올리기 전에 요금제를 꼭 확인해요**
- `pages.dev` 입구의 요청은 Workers 무료 한도에 합쳐져요. 게임 파일 같은 정적 파일 요청은 무료예요. 입구를 거치는 건 접속할 때뿐이고 게임 중 메시지 수는 같아요
- 공식 문서: https://developers.cloudflare.com/durable-objects/platform/pricing/ , https://developers.cloudflare.com/pages/functions/pricing/

## 한 판의 계산

6명, 입력 초당 10번, 195초: 591건. 입력을 초당 4번으로 줄이면 240건이에요. 깨어 있는 시간은 한 판 195초라 하루 약 530판에서 차요.

실제 서버에서 30초 판을 돌렸을 때 Cloudflare 수치로 실행 시간이 30.2초였어요. 판이 돌아가는 시간만큼 잡힌다는 계산과 맞아요. 메시지 수 대조는 수치가 늦게 집계돼 아직 끝내지 못했어요.

판이 끝날 때 결과 한 줄을 운영 상태 서버에 남겨요. 판마다 요청 1건, 저장 1줄이에요. 판이 도는지도 시작과 끝에 알려서 판마다 요청 2건이 더 들어요. 자동 배포는 판이 끝나기를 기다리는 동안 20초마다 `/live` 입구 요청 1건을 써요(10분이면 30건). 구역 밖 위치 공개는 이미 보내는 갱신에 실려 가서 메시지가 늘지 않아요.

## 열린 방 목록의 계산

목록을 보는 사람 한 명은 5초마다 입구 요청 1건을 써요. 10분 보면 120건이에요. 입구가 4초 동안 같은 목록을 나눠 써서, 목록 서버 요청은 보는 사람이 많아도 입구 서버 하나에 4초마다 1건을 넘지 않아요. 공개 방 하나는 상태가 바뀔 때마다 1건, 그 사이 2분마다 1건(시간당 30건)을 써요. 비밀 방은 목록 요청을 쓰지 않아요.

## 운영 상태의 계산

첫 화면을 열 때 `/status` 입구 요청 1건. 입구가 4초 동안 같은 상태를 나눠 써서, 상태 서버 요청은 입구 서버 하나에 4초마다 1건을 넘지 않아요. 방에 들어갈 때와 목록을 볼 때도 같은 나눠 쓴 상태를 봐요.

## 코드에 있는 안전장치

| 장치 | 위치 |
| --- | --- |
| 열쇠가 없으면 방을 못 열어요. 열쇠 설정이 없으면 아무도 못 들어와요 | `server/index.ts` |
| 허용한 사이트에서만 브라우저 접속을 받아요 | `server/route.ts` |
| 어드민에서 점검 중으로 바꾸면 새 접속을 모두 막아요. 공개 전에는 열쇠가 있어야 해요 | `server/control.ts`, `server/route.ts` |
| 입력 초당 20번 초과와 200자 초과는 버려요 | `server/room.ts` |
| 방 하나 8명까지. 대기실에서는 칸이 바뀔 때만 받아서 방이 잠들 수 있어요 | `server/room.ts` |
| 공개 방만 목록에 알리고, 바뀐 게 없으면 보내지 않아요 | `server/room.ts` |
| 목록은 입구에서 4초 나눠 쓰고, 화면은 보이는 동안에만 받아 와요 | `server/route.ts`, `client/net.js` |
| 정해진 시간을 넘긴 판, 30초간 아무도 없는 판은 멈춰요 | `server/room.ts` |
| 대기 중에는 잠들어요 | `server/room.ts` |
| 검증 도구는 올린 서버에 4명, 초당 5번, 60초를 넘겨 보낼 수 없어요 | `tools/room-check.mjs` |
| 검사 CI 는 배포하지 않아요. 배포 비밀값은 PR 이 못 읽는 `production` 환경에만 있어요 | `.github/workflows/ci.yml`, `deploy.yml` |
| 오늘 요청이나 실행량이 무료 한도의 70% 를 넘었거나 사용량을 못 읽으면 배포를 멈춰요 | `tools/usage-guard.mjs` |

## 올릴 때

`main` 에 머지되면 `deploy.yml` 이 올려요(`docs/deploy.md`). 손으로 시험 서버를 올릴 때는 `safe-deploy` 스킬을 따라요. 공개 전 시험은 열쇠를 쓰고, 사용량을 Cloudflare 숫자로 확인한 뒤에 서버를 지워요. 지운 뒤에는 그 서버의 숫자를 읽기 어려워요. 공개는 팀 결정 후에 하고, 공개 전에 한도를 넘었을 때 혼자 하기로 넘기는 화면을 먼저 만들어요.
