# 작업 방식

## 흐름

1. 이슈를 만들어요. `.github/ISSUE_TEMPLATE/` 양식의 항목을 그대로 채워요.
2. 번호를 받은 뒤 브랜치를 만들어요: `feat/#12-설명`, `fix/#12-설명`, `docs/#12-설명`.
3. `pnpm run check` 를 통과시켜요.
4. `.github/PULL_REQUEST_TEMPLATE.md` 대로 PR 을 올려요. 제목은 `feat: 문장 (#12)`.
5. CI 의 `verify` 가 통과하면 스쿼시 머지해요.

## 커밋

- 한 줄 한국어, `feat:` `fix:` `docs:` `chore:` `test:` `refactor:` 접두, 끝에 `(#번호)`
- 논리 단위로 나눠요
- 트레일러와 AI 표시는 넣지 않아요

## 화면을 바꿀 때

- 시안을 먼저 보여 주고, 담당자가 확인한 뒤 커밋해요
- 문구는 다음 행동만 말해요. 넣기 전에 Codex 로 다듬고 판정 심사를 받아요. 고치면 다시 받아요
- UI 판단 근거(가이드, 연구)는 PR 이나 문서에 남겨요
- 폰과 컴퓨터 모두 봐요. 조작은 터치가 기준이에요

## 수치를 바꿀 때

`balance-check` 스킬을 따라요. 봇 승률은 참고만 하고, 사람끼리 해 본 결과를 더 믿어요.
